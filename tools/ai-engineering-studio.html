Vom Prompt zum handelnden KI-System

Ein GPT antwortet auf einen Prompt. Ein Agent verfolgt ein Ziel, plant Schritte und nutzt Werkzeuge innerhalb definierter Grenzen. Ein Multi-Agent-System verteilt das auf spezialisierte Rollen mit Übergaben und Orchestrierung. Sieben Module führen von diesem Unterschied bis zur Live-Simulation eines Requirements Agent — mit demselben Fall als rotem Faden: der digitalen Studierendenakte.

Warum diese Unterscheidung zählt

RE-Analogie

GPT ↔ Einzelanforderung: eine Eingabe, eine Antwort, der Mensch prüft jedes Mal selbst. Agent ↔ Use Case: ein Ziel wird in Schritten verfolgt, mit Kontrollpunkten. Multi-Agent ↔ Anforderungssystem mit Rollen: mehrere Fachperspektiven, klare Übergaben, Traceability zwischen den Teilen.

Zentraler Satz

Ein Agent ist nicht einfach ein längerer Prompt. Er kombiniert Ziel, Rolle, Gedächtnis, Werkzeuge, Entscheidungslogik, Grenzen und Kontrollpunkte — genau die Bausteine, die in den nächsten Modulen einzeln gebaut werden.

Vortragsimpuls

Frag ins Publikum: „Wie viele eurer aktuellen KI-Anwendungsfälle sind eigentlich ein GPT, das ihr Agent nennt?" Meist mehr, als man denkt.

Fünf Elemente je Rolle

Jede Rolle besteht aus denselben fünf Bausteinen: Zusammenfassung, Verantwortung, Input, Output und Qualitätsregeln. Aus genau diesen fünf Bausteinen entsteht am Ende automatisch der Systemprompt — nichts davon ist zufällig formuliert.

Übergaben statt Chaos

Traceability-Analogie

Jedes Übergabeobjekt entspricht dem, was in klassischem RE eine Traceability-Verknüpfung leistet: Ein Ergebnis wird nicht neu erfunden, sondern nachvollziehbar an die nächste Rolle weitergereicht.

Die letzte Station ist kein Agent

Der letzte Schritt heißt bewusst „Human Approval" und nicht „Freigabe-Agent" — Multi-Agent-Systeme ersetzen die menschliche Entscheidung an kritischen Punkten nicht, sie bereiten sie vor.

Didaktische Erklärung

Tools = Function Calling

Jedes Werkzeug ist eine Grenzerweiterung

Technisch heißt das, was hier „Werkzeug" genannt wird, meist Function Calling oder Tool Use: das Modell darf eine definierte Funktion mit Parametern aufrufen. Jede zusätzliche Funktion vergrößert die Angriffs- und Fehlerfläche.

Analyse vs. Aktion

LLM, Dateien, Web und Datenbank sind lesende Werkzeuge — der Agent gewinnt Informationen. API, E-Mail und Kalender sind handelnde Werkzeuge — der Agent verändert etwas außerhalb seines eigenen Kontexts. Genau da beginnt Governance-Bedarf.

Diese sechs Kontrollpunkte entsprechen Meilenstein-Reviews im klassischen Projektmanagement: Nicht jeder Schritt braucht eine Freigabe, aber jeder kritische Übergang schon.

Kein Blockieren, sondern Filtern

Human in the Loop bedeutet nicht, jeden Schritt zu bremsen — sondern genau die Stellen zu markieren, an denen ein Agent Annahmen NICHT selbst treffen darf.

📘 Handbuch

Fachliches Framework: Die Modul-Reihenfolge folgt einer bewussten Eskalationslogik — erst verstehen, WAS ein Agent von einem GPT unterscheidet, dann eine Rolle bauen, dann mehrere Rollen verketten, dann Werkzeuge und Kontrollpunkte zuweisen, dann Leitplanken klären, zuletzt alles an einem Fall live sehen.

Zentraler Lernhinweis: Die häufigste Verwechslung in der Praxis ist, einen langen, gut strukturierten Prompt bereits „Agent" zu nennen. Der Unterschied entsteht erst durch Werkzeugnutzung, Entscheidungslogik und definierte Kontrollpunkte — nicht durch die Prompt-Länge.

Nachbau-Tipp: Wer ein ähnliches Studio für ein anderes Themenfeld bauen will, beginnt mit der Workspace-Shell (Sidebar-Liste + Hauptpanel + Erklär-Panel) als wiederverwendbarem CSS/HTML-Gerüst und befüllt sie modulweise mit eigenen Datenarrays — das Muster überträgt sich unverändert.

🎤 Vortrags-Skript
Einstieg (Startseite)(Startseite zeigen, noch kein Modul geöffnet)
„Fast jede KI-Anwendung, die gerade als 'Agent' verkauft wird, ist eigentlich ein GPT mit einem langen Prompt. Heute bauen wir uns durch, was einen echten Agenten wirklich ausmacht — und zwar an einem einzigen durchgehenden Fall."
Modul 1 — Vergleich(Klick durch GPT → Agent → Multi-Agent, jeweils den Ablauf zeigen)
„Schaut auf die Kontrolle-Zeile: Bei GPT steuert der Mensch jeden Auftrag direkt. Beim Agent definiert der Mensch nur noch Ziele, Freigaben und Stopppunkte. Genau dieser Kontrollverlust — bewusst gestaltet — ist der eigentliche Sprung."
Modul 2 — Agent Designer(Requirements Agent auswählen, Systemprompt zeigen, kopieren)
„Das hier ist kein Zufallsprodukt. Verantwortung, Input, Output und Qualitätsregeln stehen fest — der Systemprompt unten ist nur die Zusammenfassung dieser vier Entscheidungen."
Modul 3 — Workflow(durch die sechs Schritte klicken, Übergabeobjekte lesen)
„Jeder Pfeil zwischen zwei Agenten transportiert ein konkretes Übergabeobjekt — nicht 'irgendwie Kontext', sondern ein benanntes Artefakt. Das ist dieselbe Disziplin wie Traceability zwischen Anforderungsartefakten."
Modul 4 — Tool Studio(API oder E-Mail zuschalten, Governance-Hinweis live beobachten)
„Sobald ein handelndes Werkzeug aktiv wird, ändert sich der Hinweis unten sofort. Das ist der Moment, in dem aus 'die KI analysiert etwas' 'die KI tut etwas' wird — und genau da beginnt Governance-Pflicht."
Modul 5 — Human in the Loop(Schritt für Schritt durchklicken)
„Nicht jeder Schritt braucht eine Freigabe. Aber genau an den kritischen Übergängen — hier bei Schritt 5 — muss ein Mensch bewusst entscheiden, nicht der Agent."
Modul 6 — Governance(eine Leitplanke anklicken, Status zykeln lassen)
„Diese acht Punkte sind keine Bürokratie zum Selbstzweck — jeder einzelne verhindert ein konkretes Szenario, das ohne Klärung schiefgehen kann."
Modul 7 — Live-Simulation(Simulation starten, Protokoll live mitlesen)
„Achtet auf Schritt vier: Der Agent bereitet Rückfragen vor, statt fehlende Informationen zu erfinden. Wenn ihr euch nur einen Satz aus der heutigen Stunde merkt — dann diesen."

Allgemeine Regie-Hinweise: Modul 1 nie überspringen — ohne die Begriffsklärung wirken die folgenden Module wie Spielerei statt wie System. Beamer-Modus vor Kursbeginn einmal durchklicken. Modul 7 eignet sich als Abschluss und Zusammenfassung, nicht als Einstieg.
