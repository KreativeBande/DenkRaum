Glossar

Anforderung
Bedürfnis eines Stakeholders, Fähigkeit oder Eigenschaft eines Systems oder deren dokumentierte Darstellung. Handbuch Foundation Level, Version 1.3.3, Definition 1.1, S. 11
Funktionale Anforderung
Betrifft ein Ergebnis oder Verhalten einer Systemfunktion, auch Daten oder Interaktion mit der Umgebung. Handbuch Foundation Level, Version 1.3.3, Kap. 1.1, S. 11
Qualitätsanforderung
Bezieht sich auf Qualitätsaspekte wie Leistung, Verfügbarkeit, Sicherheit, Zuverlässigkeit. Handbuch Foundation Level, Version 1.3.3, Kap. 1.1, S. 11
Randbedingung
Anforderung, die den Lösungsraum über das Notwendige hinaus begrenzt. Handbuch Foundation Level, Version 1.3.3, Kap. 1.1, S. 11
Constraint
Requirement that limits the solution space beyond what is necessary. Foundation Level Handbook, version 1.3.3, ch. 1.1, p. 11
Functional requirement
Concerns a result or behavior of a system function, also data or interaction with the environment. Foundation Level Handbook, version 1.3.3, ch. 1.1, p. 11
Quality requirement
Refers to quality aspects such as performance, availability, security, reliability. Foundation Level Handbook, version 1.3.3, ch. 1.1, p. 11
Requirement
Need of a stakeholder, capability or property of a system, or its documented representation. Foundation Level Handbook, version 1.3.3, definition 1.1, p. 11

Handbuch

Framework und Fünf Dimensionen

Muster RTF mit Ergänzungen: Rolle (Mentor, Instructional Designer), Aufgabe (zwölf Aussagen einordnen), Kontext (Seminarpause, Beamer, offline), Format (eine HTML-Datei, zweisprachig), Eingrenzung (nur belegte Einordnung, keine Zeitagenda).

Konstruktionslogik

Die drei Kategorien stammen direkt aus den Definitionen im Handbuch. Jede Aussage passt zu genau einer Kategorie; die Erklärung verweist auf das Merkmal aus der Definition (Verhalten, Qualitätsaspekt, Einschränkung der Lösung). Sofortiges Feedback mit Fundstelle macht das Spiel zugleich zum Nachschlagewerk.

Warum kein Vertiefungs-Toggle

Spiel mit kurzen Aussagen statt Fließtext; K22 entfällt.

Zentraler Lernhinweis

Wer Anforderungen sauber einordnet, erkennt, was getestet, was gemessen und was nur eingeschränkt werden muss.

Nachbau-Tipp

Erst Definitionen mit Fundstelle sammeln, dann je Kategorie gleich viele Aussagen schreiben und die Positionen der richtigen Antwort per Skript auswerten.

Framework and five dimensions

RTF pattern with additions: Role (mentor, instructional designer), Task (classify twelve statements), Context (seminar break, projector, offline), Format (one HTML file, bilingual), Constraints (only sourced classification, no time agenda).

Construction logic

The three categories come directly from the handbook definitions. Each statement fits exactly one category; the explanation points to the feature from the definition (behavior, quality aspect, restriction of the solution). Immediate feedback with source makes the game a reference at the same time.

Why no depth toggle

A game with short statements instead of running text; K22 does not apply.

Central learning note

Whoever classifies requirements cleanly sees what must be tested, what must be measured and what is only restricted.

Rebuild tip

Collect definitions with sources first, then write the same number of statements per category and check the positions of the correct answer with a script.

Vortrags-Skript

Vorbereitung. Spiel öffnen, Beamer-Button bei Bedarf drücken.

Einstieg. Sprechtext: Gleich sehen Sie zwölf Aussagen aus einem Buchungsportal. Ordnen Sie jede ein: Was passiert, wie gut soll es sein, oder was ist vorgegeben? (Erste Aussage zeigen.)

Je Aussage. (Gruppe abstimmen lassen, dann Antwort antippen.) Sprechtext: Lesen Sie die Erklärung vor. Welches Wort in der Aussage hat Sie auf die Spur gebracht?

Abschluss. Sprechtext: Wo lagen wir daneben? Meist bei Randbedingung gegen Qualität. (Klick auf „Glossar und Quellen“.)

Regie-Hinweise. Zeitrahmen: etwa fünf bis acht Minuten. Nicht zuerst sagen: die Lösung. Erst abstimmen lassen.

Preparation. Open the game, press the beamer button if needed.

Opening. Script: you will now see twelve statements from a booking portal. Classify each: what happens, how good it should be, or what is prescribed? (Show the first statement.)

For each statement. (Let the group vote, then tap the answer.) Script: read the explanation aloud. Which word in the statement put you on the track?

Closing. Script: where were we wrong? Mostly constraint versus quality. (Click “Glossary and sources”.)

Directing notes. Time frame: about five to eight minutes. Do not say first: the solution. Let them vote first.
