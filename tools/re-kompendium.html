MASTER-BAU-PROMPT — RE-Kompendium (Requirements Engineering übergreifend) ROLLE Du baust ein interaktives, offlinefähiges HTML-Trainingstool für Requirements-Engineering-Schulungen (Zielgruppe: RE/BA/PM-Trainees ohne KI-Vorwissen). Referenzoptik: Split-Screen-Klick-Layout mit linker Kapitel-Navigation und rechtem Detail-Panel (siehe Referenztool ki-architektur-glossar-reba.html). STRUKTUR - Topbar: Marke/Untertitel links, Beamer-Toggle + Sprach-Toggle rechts. - Split-Screen: linke Spalte = Kapitel-Liste (Nummer, Titel, Kernfrage), rechte Spalte = Detail (Badges, Titel, Kernfrage, Persona-Zitat, Vertiefungs-Toggle, Inhalt, Mini-Quiz). - Vier Footer-Boxen: Systemprompt (dieser Prompt), Handbuch (didaktisch), Vortrags-Skript (Sprechtext), Normen-Register (referenzierte Standards mit Stand/Datum). - Signatur oben rechts, position:fixed, Name + Website-Link, auf jeder Viewport-Breite (kein static-Fallback). INHALT PRO KAPITEL - Badges (referenzierte Normen), Nummer/Titel/Kernfrage, Persona-Zitat (feste Vantera-Personas: Ela/Knut/Sarah/Petra/Bachmeier, farbcodiert), Kurzversion (destilliert) + Vollversion (vierstufiger Anreicherungs- Pass: Lückenanalyse, Anreicherung mit Beispiel/Definition/Kontext, Stiloptimierung, Substanzverdreifachung), TalentMatch-AI-Beispielbox, Mini-Quiz mit sofortigem Feedback. TOGGLES (alle drei Pflicht, von Anfang an mitbauen) 1. Beamer-Toggle (vierstufig): Normal -> Beamer -> Beamer XL -> Beamer XXL -> Normal. Reine Groessensteigerung. Footer ab Stufe 1 ausgeblendet. Erzwingt automatisch die Kurzversion der Vertiefung, unabhaengig vom vorherigen Nutzerzustand; beim Verlassen wird der vorherige Zustand wiederhergestellt. 2. Sprach-Toggle DE/EN: alle sichtbaren Texte inkl. aller vier Footer-Boxen, ohne Reload, ohne externen Uebersetzungsdienst. 3. Vertiefungs-Toggle (kurz/voll): Default kurz, beide Versionen statisch im HTML, session-persistent. NICHT TUN - Keine Normbezug-Stempelmarken/Audit-Status-Zeile in der Signatur. - Keine Nachbau-Tipp-Zeile im Handbuch. - Kein Dark Mode, kein fetch() auf externe Hosts, kein CDN. - Keine generischen Werte/Platzhalter — jede Zahl/Frist/Norm konkret und mit Stand/Datum belegt. TECHNIK Single-file HTML, color-scheme:light, pointerup statt click, sessionStorage nur mit try/catch, min. 16px Fliesstext / 14px Sekundaertext, 44px Touch-Ziele, UTF-8 direkt ohne Escape-Sequenzen.
MASTER BUILD PROMPT — RE Compendium (cross-standard Requirements Engineering) ROLE You are building an interactive, fully offline HTML training tool for requirements engineering education (audience: RE/BA/PM trainees with no prior AI knowledge). Reference look: split-screen click layout with a left chapter navigation and a right detail panel (see reference tool ki-architektur-glossar-reba.html). STRUCTURE - Topbar: brand/subtitle left, Beamer toggle + language toggle right. - Split screen: left column = chapter list (number, title, key question), right column = detail (badges, title, key question, persona quote, Vertiefung toggle, content, mini quiz). - Four footer boxes: System Prompt (this prompt), Handbook (didactic), Speaker Script, Norms Register (referenced standards with date/status). - Signature top-right, position:fixed, name + website link, on every viewport width (no static fallback). CONTENT PER CHAPTER - Badges (referenced norms), number/title/key question, persona quote (fixed Vantera personas: Ela/Knut/Sarah/Petra/Bachmeier, color-coded), short version (distilled) + full version (four-step enrichment pass: gap analysis, enrichment with example/definition/context, style optimization, substance tripling), TalentMatch AI example box, mini quiz with instant feedback. TOGGLES (all three mandatory, built in from the start) 1. Beamer toggle (four-stage): Normal -> Beamer -> Beamer XL -> Beamer XXL -> Normal. Pure size increase. Footer hidden from stage one. Automatically forces the short Vertiefung version regardless of prior user choice; the prior state is restored on exit. 2. Language toggle DE/EN: all visible text incl. all four footer boxes, no reload, no external translation service. 3. Vertiefung toggle (short/full): default short, both versions static in the HTML, session-persistent. DO NOT - No norm-reference stamps/audit-status line in the signature. - No rebuild-tip line in the handbook. - No dark mode, no fetch() to external hosts, no CDN. - No generic values/placeholders — every number/deadline/norm concrete and backed with a status/date. TECH Single-file HTML, color-scheme:light, pointerup instead of click, sessionStorage only with try/catch, min. 16px body text / 14px secondary text, 44px touch targets, direct UTF-8, no escape sequences.
Handbuch

Framework: RAKFE (Rolle · Aufgabe · Kontext · Format · Eingrenzung) — Michaelas eigenes Prompt-Framework, hier auf den Tool-Bau-Prompt selbst angewendet.

  • Rolle: "Trainingstool-Entwicklerin für RE/BA/PM-Schulungen" — nicht "Requirements Engineer", weil die Aufgabe didaktische Aufbereitung ist, nicht die Anforderungsarbeit selbst.
  • Aufgabe: ein Kompendium bauen, das drei Standards (IREB/BABOK v3/IEEE 29148) nebeneinander verständlich macht — nicht nur einen davon vertiefen.
  • Kontext: Vantera/TalentMatch-AI-Fallstudienwelt als durchgängiges Beispiel, feste Personas mit klaren Rollen und Farbcodes.
  • Format: Split-Screen-Klick-Kompendium mit Kapitel-Navigation (nicht Begriffs-Lexikon) — weil "vollständig und ausführlich" mehr Tiefe pro Einheit braucht als ein Glossar leisten kann.
  • Eingrenzung: keine Stempelmarken, keine Nachbau-Tipp-Zeile — auf expliziten Wunsch entfernt, um den Fokus auf Inhalt statt Meta-Ebene zu legen.

Zentraler Lernhinweis: Der wichtigste didaktische Kniff dieses Tools ist Kapitel 9 (Normen-Mapping) — es zeigt explizit, wo Standards sich NICHT decken (z. B. BABOK 5.5 ohne IREB-Pendant). Genau diese Lücken sind es, an denen Lernende typischerweise scheitern, wenn sie Standards nur additiv statt vergleichend lernen.

Framework: RAKFE (Role · Task · Context · Format · Constraints) — Michaela's own prompting framework, applied here to the tool-build prompt itself.

  • Role: "training tool developer for RE/BA/PM education" — not "requirements engineer", because the task is didactic preparation, not requirements work itself.
  • Task: build a compendium that makes three standards (IREB/BABOK v3/IEEE 29148) understandable side by side — not deepen only one of them.
  • Context: the Vantera/TalentMatch AI case study world as a running example, fixed personas with clear roles and color codes.
  • Format: split-screen click-compendium with chapter navigation (not a term glossary) — because "complete and thorough" needs more depth per unit than a glossary can deliver.
  • Constraints: no stamps/seals, no rebuild-tip line — removed on explicit request to keep the focus on content rather than the meta level.

Central learning point: this tool's most important didactic trick is Chapter 9 (norms mapping) — it explicitly shows where standards do NOT align (e.g. BABOK 5.5 with no IREB counterpart). It is exactly these gaps where learners typically stumble when they learn standards additively rather than comparatively.

Vortrags-Skript

(Klick: Tool öffnen, Kapitel 1 aktiv) "Wir starten mit einer Frage, die in fast jedem Projekt zu Missverständnissen führt: Was ist eigentlich der Unterschied zwischen Requirements Engineering, Business Analysis und Projektmanagement? Schauen wir uns die drei Definitionen nebeneinander an..."

(Klick: Vertiefungs-Toggle auf "Vollständig") "Wer mehr Tiefe braucht, klappt hier auf — inklusive einem konkreten TalentMatch-AI-Beispiel, wie die Rollentrennung in der Praxis aussieht."

(Klick: Kapitel 6, Qualitätskriterien) "Das hier ist für mich das wichtigste Kapitel im ganzen Kompendium — sieben Kriterien, die für JEDE Anforderung gelten, egal in welchem Format sie geschrieben ist."

(Klick: Kapitel 9, Normen-Mapping) "Und zum Schluss die Landkarte: Wo decken sich die drei Standards, und wo eben nicht? Genau an den Lücken lernt man am meisten."

(Klick: Beamer-Toggle) "Für die Projektion vergrößere ich jetzt die Ansicht — das schaltet automatisch auf die Kurzversion um, damit es auf der Leinwand lesbar bleibt."

Regie-Hinweise: Nicht mit Kapitel 9 (Normen-Mapping) beginnen — wirkt ohne die vorherigen acht Kapitel abstrakt und akademisch. Zeitbudget: ca. 8–10 Minuten pro Kapitel bei Live-Diskussion, das ganze Kompendium sprengt eine 90-Minuten-Session — für kürzere Formate 3–4 Kernkapitel vorab auswählen.

(Click: open tool, Chapter 1 active) "We start with a question that causes misunderstandings in almost every project: what's the actual difference between requirements engineering, business analysis and project management? Let's look at the three definitions side by side..."

(Click: Vertiefung toggle to "Full") "Anyone who needs more depth can expand here — including a concrete TalentMatch AI example of what the role separation looks like in practice."

(Click: Chapter 6, Quality Criteria) "This is, for me, the most important chapter in the whole compendium — seven criteria that apply to EVERY requirement, no matter which format it's written in."

(Click: Chapter 9, Norms Mapping) "And finally the map: where do the three standards align, and where don't they? It's exactly at the gaps that people learn the most."

(Click: Beamer toggle) "For projection I'll now enlarge the view — this automatically switches to the short version so it stays readable on the screen."

Directing notes: don't start with Chapter 9 (norms mapping) — without the preceding eight chapters it feels abstract and academic. Time budget: roughly 8–10 minutes per chapter with live discussion; the full compendium exceeds a 90-minute session — for shorter formats, pre-select 3–4 core chapters.
